THE IDEA

It should remember
what you said.

The goal is to build context over several turns rather than treating each message as an isolated search query. The system can search locally sourced passages and decide when another user detail would help.

01 / LISTEN
⌁

Speak naturally

Whisper.cpp transcribes English speech on the phone. Typed questions follow the same path.

02 / REMEMBER
◫

Build context

Keep relevant user-reported information and corrections in a bounded conversation state.

03 / RETRIEVE
⌕

Find evidence

MiniLM vectors and SQLite text search retrieve passages from an offline medical corpus.

04 / RESPOND
✧

Choose next action

Qwen proposes a question, answer or knowledge-gap message for validation before presentation.

TECHNOLOGY

Purpose-built
for the device.

A separate small component for each task, without a remote medical inference REST API or cloud vector database.

WBaseline

Whisper.cpp

Offline English speech recognition using a quantized Tiny Q5 model.

AudioRecord · JNI · C++
MPrototype

MiniLM-L6-v2

384-D sentence embeddings using an INT8 ONNX model on Android CPU.

ONNX Runtime · WordPiece
DPrototype

Local search

SQLite FTS4, compact exact vector index and reciprocal rank fusion.

SQLite · VEC1 · RRF
QBaseline

Qwen3-0.6B

One local small language model for conversation planning and educational replies.

GGUF Q4_K_M · llama.cpp
RBaseline

Room + SQLite

Opt-in conversation history, kept separate from the medical search database.

Kotlin · Room · StateFlow
CBaseline

Jetpack Compose

Android doctor UI with press-to-talk, chat, local TTS and model status.

Kotlin · MVVM · Material 3
PROJECT STATUS

Built in phases.
Verified honestly.

The Phase 4 code and offline medical assets are committed to GitHub. Some retrieval, grounding and conversational behavior needs correction; the Android prototype has not passed a full physical-device and clinical evaluation.
